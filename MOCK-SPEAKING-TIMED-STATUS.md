# Timed Speaking prompt draft

The timing module and rehearsal are connected to the authenticated POST dispatcher and consolidated draft bundle on feature/academic-lab-mock, draft PR 6. User approval covered this narrow connection only. All gates remain disabled and nothing was deployed.

## Draft behavior

MockSpeakingTimed.gs validates the pinned private paper digest and speakingTiming.reviewed === true. It uses the existing authenticated candidate, written-test completion and owner-private storage checks. The existing dispatcher passes the verified session context and holds its script lock for start/resume.

Private schema:
- speakingTiming.part1: 4–12 objects containing prompt and integer seconds; total 240–300 seconds.
- speakingTiming.cue: nonempty plain text, at most 3,000 characters.
- speakingTiming.part3: 4–8 prompt/seconds objects; total 240–300 seconds.
- Each question is 15–90 seconds. Prompt text is bounded and rendered as text.
- The cue appears for 60 seconds of preparation and then 120 seconds of speaking.
- Total timing is 11–13 minutes. The real IELTS Speaking format is 11–14 minutes, with Part 1 and Part 3 at 4–5 minutes and Part 2 preparation of one minute plus a talk up to two minutes. See [IELTS Speaking format](https://ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-speaking).

Only the current prompt is returned; future prompts, answer keys and assessment material are excluded. The original start is stored in the attempt state with its pinned paper digest. Refresh, client clock values and repeated start requests cannot restart the timer. At the final deadline no prompt is returned.

The mock-speaking-timed.html screen is a timing rehearsal: microphone permission preflight, consent, current question/countdown, resume after refresh and visible connection errors. It does NOT record audio. Preflight flags are client declarations, not trusted proof of an audio recording. This is a fixed prompt schedule, not an interactive examiner or AI assessment.

Tests now call through the real handler rather than invoking the module directly; browser tests still use a synthetic service.
